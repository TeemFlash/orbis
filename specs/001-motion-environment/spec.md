## User Scenarios & Testing *(mandatory)*

### User Story 1 - Показания внутри Semey Map (Priority: P1)
Пользователь открывает Sensors с карты и видит текущие X/Y/Z в м/с² и освещённость в люксах. Доступ не зависит от входа в чат.

**Why this priority**: Это основа лабораторной и точка интеграции в существующее приложение.
**Independent Test**: Открыть Sensors, изменить положение телефона и освещение; проверить значения, затем вернуться на карту.
**Acceptance Scenarios**:
1. **Given** датчик доступен, **When** поступило измерение, **Then** показано значение с единицами, без ручного обновления.
2. **Given** датчика нет или его запуск не удался, **When** открыт экран, **Then** показано соответствующее состояние, а доступный датчик продолжает работать.
3. **Given** экран закрыт или приложение свёрнуто, **When** телефон движется, **Then** сбор данных остановлен; после возврата восстанавливается один раз.

### User Story 2 - Реакция на наклон (Priority: P2)
Шар в ограниченной области движется при наклоне телефона.

**Why this priority**: Демонстрирует использование показаний в интерактивном UI.
**Independent Test**: Наклонить устройство в четыре стороны и вернуть его в горизонтальное положение.
**Acceptance Scenarios**:
1. **Given** получены измерения, **When** меняется наклон, **Then** шар плавно смещается по экранным осям и остаётся внутри области.
2. **Given** смена ориентации экрана, **When** пользователь наклоняет телефон, **Then** направление реакции соответствует экрану, без вылета шара за границы.
3. **Given** акселерометр отсутствует, **When** открыт экран, **Then** шар неподвижен, причина видна текстом.

### User Story 3 - Автоматическая тема (Priority: P2)
Экран датчиков переключает светлую и тёмную схемы по освещённости.

**Why this priority**: Выполняет требование автоматического режима.
**Independent Test**: Закрыть датчик света и затем осветить его; проверить цвета и читаемость.
**Acceptance Scenarios**:
1. **Given** устойчиво темно, **When** поступают показания света, **Then** экран становится тёмным.
2. **Given** устойчиво светло, **When** поступают показания, **Then** возвращается светлая схема.
3. **Given** свет колеблется около границы, **When** продолжаются измерения, **Then** тема не мигает.
4. **Given** света нет в устройстве или ещё не получено измерение, **Then** используется системная тема и виден статус датчика.

### Edge Cases
- Нет одного или обоих датчиков; отказ регистрации; задержка первого события.
- Реальный нулевой lux не равен отсутствию данных.
- Быстрый переход карта → Sensors → чат, сворачивание, поворот и повторное открытие.
- Сильная встряска: шар ограничен областью, некорректные числовые значения игнорируются.

## Requirements *(mandatory)*

### Functional Requirements
- **FR-001**: Экран Sensors открывается из Semey Map, имеет возврат на карту; новый APK или отдельное приложение для задания не создаётся.
- **FR-002**: Показывать X/Y/Z с единицами м/с², lux и отдельное состояние каждого датчика.
- **FR-003**: Обновлять показания автоматически при получении событий.
- **FR-004**: При наклоне двигать шар внутри его области с плавным переходом.
- **FR-005**: Автоматически менять тему экрана датчиков по свету без мерцания.
- **FR-006**: Останавливать сбор при уходе с экрана и восстанавливать без дублирования.
- **FR-007**: Работать без сети и без новых запросов входа; не отправлять измерения в облако.
- **FR-008**: Сохранять существующие функции карты, чата и фотографий.
- **FR-009**: Обработать отсутствие датчиков и не выдавать подставные значения за измерения.
- **FR-010**: Проверить сценарии на эмуляторе с вводом датчиков или на физическом устройстве, явно указав способ проверки.

### Key Entities
- Показание: оси ускорения, освещённость, время последнего события, статус доступности.
- Состояние экрана: показания, положение шара и текущая тема; только оперативная память.

## Success Criteria *(mandatory)*

### Measurable Outcomes
- **SC-001**: Sensors доступен одним нажатием с карты; Back возвращает карту.
- **SC-002**: При тестовом изменении датчика значение и визуальная реакция видимы в пределах 0,5 секунды после события.
- **SC-003**: Во всех четырёх направлениях наклона шар остаётся внутри области, включая поворот экрана.
- **SC-004**: При тестовых 10 lux и 100 lux выбираются соответственно тёмная и светлая схемы; промежуточные колебания не переключают тему.
- **SC-005**: После 10 циклов открытия/закрытия нет повторных подписок; в фоне нет обработки измерений.
- **SC-006**: Отсутствие каждого датчика по отдельности и обоих вместе не вызывает сбоя; карта и чат продолжают открываться.

## Assumptions
- Используются акселерометр и свет: конкретный BLE-периферийный прибор, сервисы и характеристики в задании не заданы. BLE и гироскоп не входят в этот план.
- Автотема действует на новом экране Sensors; переработка темы всех существующих Java-экранов не требуется заданием и в план не входит.
- Английские подписи и светлая голубая/мятная палитра сохраняются по предыдущему выбору пользователя.
- Пороговые значения и фильтрация — решения реализации, а не цитата из задания; их фиксирует plan.md.
- Существующие артефакты LivePulse и настройки Firebase сохранены после отмены предыдущей работы; удаление или откат не входит в эту спецификацию.

## Approved Profile addendum (2026-11-10)
- **FR-011**: Four bottom destinations Map, Chats, Sensors, Profile; Sensors and Profile work for guests.
- **FR-012**: Profile follows supplied visual hierarchy: full-bleed cover, dark gradient lower panel, centered identity, rounded edit button/bio card and top-right settings. Until a user selects a photo, use an initials/gradient placeholder. No invented identity, social counts or follow behavior.
- **FR-013**: Edit display name, bio and photo locally with Save/Cancel; scope details to current auth UID or guest. Existing Firebase chat identity remains unchanged; disclose device-local storage.
- **FR-014**: Settings persists Auto sensor theme (enabled by default), shows actual account identity and app version. Disabled auto-theme uses system theme on Sensors; live sensor readings continue.
- **SC-007**: Profile edits survive relaunch, Cancel preserves previous values, switching accounts does not expose another local profile.
- **SC-008**: Settings toggle changes Sensors theme behavior after navigation; all four tabs remain usable on a narrow phone.
